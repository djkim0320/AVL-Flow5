# 범용 모델 등록과 AVL + flow5 복합 공력표 구현 기록

2026-09-28 · 기준 문서: `docs/HYBRID_AERO_HANDOFF.md`

Part A의 내장 기체 의존성을 제거한 뒤 Part B의 엄격한 공력표 조합과 UI 연결을 구현했다. 기본 조합의 실제 공력표 생성은 확인했으나, 시험 기체의 대칭 트림은 횡방향 잔차 때문에 실패했다. 정적 계수 출처를 사용자가 AVL로 선택한 별도 조합에서는 트림·고유모드·짧은 시간응답까지 완료했다. 두 결과를 구분해서 보존한다.

## 변경 내용

| 영역 | 구현 |
|---|---|
| 모델 등록 | 32자리 등록 ID와 CAD·기체 정의 해시로 연결. 미등록·다른 형상·다른 기체 정의는 거부 |
| 빈 상태 | 등록 모델이 없으면 실행 비활성화와 기체 정의 안내. 없어진 저장 모델을 자동으로 다른 모델로 바꾸지 않음 |
| 윈치 | 표시용 드럼·받침 생성, 줄 출구를 원점으로 사용, 기체 중심선 배치 |
| 고급 입력 | 물리값이 null인 중립 YAML과 항목별 단위·좌표·출처 안내. 빈 템플릿 및 표시 플래그만 바꾼 템플릿도 등록 거부 |
| 접촉 | 명시적 parts_manifest 필수. 기존 예제에는 형상·역할·좌표·접촉 방식 명시. 사용자 실행 파일은 수정하지 않음 |
| 계산 자원 | 공용 compute_resources 모듈. 가능하면 4 CPU를 남기고 최대 12 사용. 복합 계산은 두 해석기에 작업 수 분배, AVL 메모리 상한 유지 |
| 공력 조합 | coeff / controls / rates를 AVL 또는 flow5에서 선택. 세 블록이 같은 출처면 단일 해석기를 요구 |
| 불변 조건 | 동일 형상·참조 파일 해시, 동일 격자, 기준 치수 상대 1e-5, 기준점 절대 1e-9 m 검사. 양쪽 CG 일치와 실제 실행 AVL 사본 헤더 확인 |
| 추적 정보 | 양쪽 원본 npz·실행 폴더·해시·버전·속도·선택/제외 블록 보존. 격자 중앙 또는 경계에서 다섯 기울기 비교 |
| UI | 복합 해석기, 출처 선택 3개, 승강타 ±10° 검사, 설정 저장·복원, 저장 표 재사용 검사, 비교표와 20% 차이 경고 |
| 실패 표시 | 복합 공력표 생성 뒤 트림이 실패해도 출처·비교·원본 파일은 결과 카드에 유지 |

주요 파일: `src/dbf_stability/hybrid.py`, `compute_resources.py`, `avl.py`, `flow5.py`, `collision.py`; `ui/model_registry.py`, `server.py`, `analysis_bridge.py`, `analysis_worker.py`, `aircraft_definition.py`, `analysis-*.js`, `aero-ranges.js`, `app.js`.

추가로 질점 해석이 사용하지 않는 장치 접촉 검사에 막히던 문제와, 방출 시각이 0일 때 길이 이력의 시각 0이 중복되던 문제를 수정했다. 단일 공력 해석기의 계수 계산식과 트림 허용치는 바꾸지 않았다. 새 flow5 표에는 계산 속도 메타데이터를 추가했다.

시험 형상은 이 작업에서 만든 직사각 주익·수평미익·수직미익이며 팀 기체 예측값이 아니다. 8768 검증 서버는 격리된 등록 폴더를 사용했고 실제 해석 작업과 원본 출력은 `ui/data/analysis/`의 새 실행 폴더에 남겼다.

마지막 실행의 트림은 받음각 2.412321°, 승강타 −1.129869°, 추력 3.187325 N이다. 가장 큰 성장률은 0.046777 /s이며 불안정 모드를 검출했다. 이 짧은 실행은 연결 검사다. 장시간 비행, 회수 성공, 메시·시간 간격 수렴이나 실물 정확도를 확인한 결과로 해석하면 안 된다.

각 폴더의 `request.json`, `aero_metadata.json`, `avl/`, `flow5/`, `solver.log`에서 입력과 실제 계산 근거를 확인한다. 완료된 실행에는 `trim.json`, `modes.csv`, `state_matrix.npy`, `simulation/`, `report.html`도 있다. 원본을 보존한 별도 조합 실험은 이 폴더의 `alternative-composition.npz`다.

## 계획과 달라진 부분·남은 제한

- `/api/models/template`은 모델이 없는 첫 등록에서도 필요하므로 모델 ID 없이 중립 템플릿을 제공한다. catalog에는 모델 ID가 필요하다.
- 2점 격자는 중앙차분을 할 수 없어 경계 차분을 사용하고 메타데이터에 방법·계산점·간격을 기록한다.
- 현재 `model.py`는 모든 공력 블록을 합한 후 모멘트 팔을 적용한다. 계획의 “정적 계수에만 적용” 설명을 정정했다. 복합 표의 회전 중심은 CG 일치 검사로 제한한다.
- 기본 flow5 정적 계수의 작은 횡방향 잔차를 처리하는 비대칭 트림은 구현 범위에 넣지 않았다. 계수 0 대체, 허용오차 완화, 자동 출처 변경은 하지 않는다. 공력표 생성 성공과 트림 성공을 구분한다.
- 격자·기준점이 다른 저장 표를 보간·이동하는 선택 사항 B5는 구현하지 않았다.
- 기존 H1·N3 산출물과 사용자 프로젝트·기존 결과를 삭제하거나 덮어쓰지 않았다. 검증용 모델 등록은 별도 폴더이며 실제 사용자 목록에 추가하지 않았다.

진행 중 작업이 없는 것을 확인하고 운영 서버 8767을 재시작했다. [사용설명서](../../../docs/사용설명서.md), [flow5 연결 문서](../../../docs/FLOW5_CONNECTION.md), [물리모델 문서](../../../docs/MODEL.md), UI·루트 README를 갱신했다.
