## 검증

- `check-drag.js`, `check-assembly.js`: 센서와 윈치를 실제 마우스로 이동하고 센서 표면을 우클릭했다. 모델의 위치 변화, 표면 연결점 유지, 줄 거리 갱신, 되돌리기·다시 실행, 파일 저장 후 재열기를 확인했다. CLI가 파일 선택 창 상태를 먼저 반환하는 문제는 조작 완료 기록과 이후 독립적인 복원 검사로 확인했다.
- `check-imports.js`: 기존 CAD의 센서 STEP와 STL을 읽었다. 길이는 각각 0.1199808135 m, 0.1199808419 m. GLB는 37개 메시를 읽었다. 손상 파일은 기존 모델을 교체하지 않았다. JSON의 모델·줄 데이터가 새로고침 후 동일했다.
- `check-layout-export.js`, `check-final.js`: 위치·회전 및 연결점을 키보드로 입력했다. 기체 이동·90° 회전 후 배치 내보내기를 수행했다. 줄 길이 부족과 기체 표면 교차 표시를 확인했다. 빈 곳 우클릭은 기존 연결점을 바꾸지 않았다.
- 1440/720/320 px에서 문서 너비와 화면 너비가 일치했다. 최종 320 px 캔버스 높이는 약 472 px다. `final-*.png`를 직접 확인했다. 720 px는 좁은 화면 재배치 검사이며 실제 브라우저 확대 배율 시험을 대신했다고 주장하지 않는다.
- 본문·보조 설명·주요 버튼·경고의 실제 CSS 색상 대비를 계산했다. 선택 정보는 테두리·텍스트로도 제공된다. `prefers-reduced-motion`에서 불필요한 애니메이션이 없으며 키보드 초점의 outline을 확인했다.
- `.venv/Scripts/python.exe -m unittest discover -s ui/tests -v`: 실제 UI 저장 데이터에 대한 표면 일치, 잘못된 연결점·좌표·인덱스·줄 설정 거부, 기체 기준 내보내기 등 **5개 테스트 통과**.
- `npm.cmd run check`: JS 문법 검사 통과. 최종 Chrome 세션 로그는 검증용 INFO만 기록했고 실행 오류는 없었다.
- Codex 내장 브라우저에서도 H1 모델 불러오기를 확인했다.

**확인하지 않은 항목:** 스크린리더의 실제 음성 출력, 실제 모바일 터치 장치, 대규모 CAD의 성능 한계, 다중 사용자 편집. 물체 간 접촉이나 비행 물리는 이 편집기의 검증 범위가 아니다.
