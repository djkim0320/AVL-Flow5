# DBF 질점·견인선 해석 UI

문이 열린 기체를 불러온 뒤 **윈치 위치 → 질점 질량 → 줄 길이**를 설정한다. 센서 CAD 불러오기, 센서 회전·표면 연결점 지정 기능은 제거했다. 센서 역할의 질점은 형상 없이 계산하며, 화면의 구는 위치 표시용이다.

## 실행

처음 사용하는 경우 [DBF Studio 사용설명서](../docs/사용설명서.md)의 순서대로 기체 배치·부품 지정·CG 입력·모델 등록·해석을 진행한다. 새로 받은 저장소의 설치 명령은 [루트 README](../README.md#github에서-받아-실행하기)에 있다.

프로젝트 폴더의 [Start_DBF_UI.bat](../Start_DBF_UI.bat)를 더블클릭한다. 실행 중인 서버가 있으면 재사용한다. 브라우저를 닫아도 서버와 해석은 계속 실행된다.

[DBF Studio 열기](http://127.0.0.1:8767/)

직접 실행할 때는 프로젝트 폴더에서 아래 명령을 사용한다.

```powershell
.venv\Scripts\python.exe ui\server.py --port 8767 --workers 2
```

STEP 변환용 작업자 수와 해석의 CPU 설정은 별개다. 해석은 최대 12개 CPU를 사용하며 모든 계산 단계가 병렬인 것은 아니다. 새 서버의 로그는 `ui/data/launcher`에 저장된다.

## 배치

1. 기체 STEP·STL·GLB를 파일 선택 또는 3D 화면에 드래그해 불러온다. 최근 가져온 파일도 다시 끌어넣을 수 있다. 새 기체를 불러오면 기존 윈치·질점 배치는 비워진다. 센서 파일은 사용하지 않는다.
2. **윈치 추가**를 누른 뒤 드래그하거나 오른쪽 좌표 입력으로 위치를 정한다. 파란 점이 줄 출구다. 윈치는 기체 중심선(기체 정의의 전체 CG Y, 없으면 CAD Y=0)에 놓인다. 견인 트림은 좌우 대칭만 지원하므로 Y는 중심선에 둔다. 측면 보기에서 드래그하거나 X·Z 화살표를 쓰면 Y가 유지된다.
3. **센서 역할 질량(kg)**과 **전개할 줄 길이(m)**를 입력하고 **질점 추가 · 줄 자동 연결**을 누른다.
4. 질점은 윈치에서 기체 하방으로 줄 길이만큼 떨어진 곳에 표시된다. 윈치와 줄 길이를 바꾸면 같이 이동한다. 이 직선 그림은 길이 확인용이며 비행 중 평형·처짐·접촉을 나타내지 않는다.
5. **해석**에서 기체·줄 물성과 비행 조건을 확인하고 실행한다. **파일 저장**으로 기체와 윈치 형상, 질점 질량, 줄 설정, 해석 조건을 함께 저장한다.

배치 화면의 초기 질량·줄 길이는 입력 시작값이다. 팀 기체의 실측값으로 바꿔야 한다. 줄 직경은 3단계의 세부 설정에, 선밀도·강성·감쇠·항력은 해석 화면에 있다. 해석 조건은 전개 비행과 회수 두 가지다. 둘 다 줄이 완전히 전개된 비행 평형에서 시작한다.

빈 곳 드래그는 시점 회전, 휠 버튼을 누른 채 드래그하거나 우클릭 드래그하면 화면 기준 상하좌우로 시점을 이동한다. 휠을 굴리면 확대·축소한다. 결과 재생 화면도 같은 조작을 사용한다. 윈치는 직접 드래그하거나 G 이동 도구를 사용한다. 질점은 독립적으로 이동·회전하지 않는다. Ctrl+Z와 Ctrl+Shift+Z로 배치·질량·줄 길이 변경을 되돌릴 수 있다.

## 기체 방향과 공기 흐름

해석은 기체 CAD의 **+X를 앞**으로 보며, 공기는 +X에서 −X로 흐른다. 3D 화면의 청록색 화살표와 "공기 흐름" 라벨이 이 방향과 해석 속도를 표시한다. 장면의 **공기 흐름 방향 표시**로 끄고 켤 수 있다. 받음각·승강타는 트림에서 계산하므로 화살표는 기체 X축 기준 방향만 나타낸다.

화살표가 기체 코 쪽에서 오지 않으면 기체를 선택하고 **해석 기준 방향**의 X·Y·Z ±90° 버튼으로 보정한다. 보정은 화면 자세가 아니라 CAD 꼭짓점 자체를 돌리며, 적용한 회전을 파일 출처(`source.orientation_turns`, `orientation_matrix`)에 기록한다. 윈치는 기체와 함께 돌아간다. 형상이 바뀌므로 기존 등록 모델과의 연결은 풀린다. 기체 정의 좌표는 현재 방향 기준이라, 정의에 값을 입력한 뒤에는 방향 보정을 막는다. 방향을 먼저 맞춘다.

기체의 화면 표시 회전(자세)은 해석 축을 바꾸지 않으므로 기체에는 제공하지 않는다. 이전 파일에 표시 회전이 남아 있으면 **화면 표시 회전을 0으로 되돌리기**가 나타나며, 윈치도 기체와 함께 옮긴다.

## 기체 정의 · 부품 / CG / 공력 면

새 기체의 부품 역할, CG 드래그·좌표, 전체 또는 부품별 질량·관성, CAD 단면·조종면·추진 입력을 화면에서 설정할 수 있다. **기체 정의 · 부품 / CG / 공력 면**을 눌러 시작한다. 등록하면 현재 기체의 AVL 입력이 생성되고 해석 모델로 연결된다. 패널을 열어 보기만 해서는 정의가 프로젝트에 저장되지 않는다. 역할·질량·CG·공력 면 등을 처음 입력할 때부터 저장되며, 그때부터 새 버전 등록이 필요하다. 상세 사용법과 검증 범위는 [기체 정의 안내](../docs/aircraft_definition.md)를 참고한다.

## 공력 범위 슬라이더

받음각·옆미끄럼각·승강타각은 최소·최대·계산점 수 슬라이더로 설정한다. 변경한 각도의 계산점은 균등 간격으로 생성되며 전체 조합 수를 바로 표시한다. 저장된 비균등 계산점은 해당 슬라이더를 조작하기 전까지 유지한다. 기존 공력표를 선택하면 슬라이더가 잠기며, 새 계산 또는 다시 계산을 선택해야 편집할 수 있다.

## 물리 모델과 해석 범위

- 기체: 등록 형상과 일치하는 실제 MIT AVL/flow5 공력표를 사용하는 6자유도 강체.
- 센서: 질량과 병진 운동만 있는 질점. 중력과 줄 장력을 받고, 연결 위치는 질점 자체다. 센서 공력·회전·관성·형상 접촉은 계산하지 않는다.
- 줄: 기존 분할 모델의 질량·공력·탄성·감쇠를 사용한다. 질점 하중과 윈치의 반력을 기체에 함께 적용한다.
- 트림·고유값: 고정 길이의 기체–질점–줄 평형을 계산한다. 고유값 계산에서 센서 회전 자유도는 제외한다. 현재 견인 트림은 좌우 대칭 윈치 위치만 지원한다.
- 시간응답: 평형 교란 또는 윈치 아래 질점 위치에서 시작한다. 그 위치를 평형으로 가정하지 않는다. 조종 입력·돌풍·명시적인 제어 설정은 유지한다.
- 전개 비행: 트림과 제어가 없는 고정 길이 평형의 고유값을 계산한 뒤, 지정 시간의 응답을 계산한다. 제어·돌풍·조종 이력은 시간응답에만 적용한다.
- 회수: 완전 전개 평형에서 바로 줄을 감는다. 회수 평균 속도와 남길 줄 길이로 소요 시간을 정하며 전개·유지 구간은 없다. 줄 길이는 완만한 가감속 곡선을 20구간으로 나누어 적용하고, 줄 분할 경계에서도 적분을 다시 시작한다. 문은 불러온 각도를 유지하며 포획·문 닫힘은 계산하지 않는다. 회수 목표 길이 도달은 실물 포획 성공 판정이 아니다.

CAD가 보인다고 CAD 접촉을 계산하는 것은 아니다. 기체를 가로지르는 미리보기 선은 교차 위치를 표시하지만 해석의 충돌 제약으로 사용하지 않는다. 물리적으로 통과 가능한 회수 장치나 충격 안전성을 이 질점 모델로 입증할 수 없다.

기체를 바꾸면 해당 기체의 물성·공력 형상을 등록해야 한다. CAD와 등록 정보가 일치하는 기체의 공력표만 사용할 수 있다. 새 모델 등록에도 센서 CAD·센서 CG·센서 관성은 필요 없다. 기체 질량·CG·관성과 공력 기준치는 직접 입력한다. 윈치 이동에 따른 기체 질량 분포 변화는 자동 추정하지 않는다.

저장된 flow5 표는 해당 실행의 계산 속도에서 만든 동체 제외 VLM2 결과다. 속도가 다르면 새 계산이 필요하며, 트림 잔차 기준을 통과하지 못하면 안정성 해석을 중단한다. 계산 완료는 안전성이나 수치 수렴 판정이 아니다.

## 좌표와 저장

내부 계산과 파일은 m·FRD(X 전방, Y 우측, Z 하방), 화면의 위치 입력은 mm다. 기체 파일 원점을 유지하며 해석 등록 시 물리 CG를 따로 지정한다. STEP은 mm로 변환하고 STL·GLB는 입력 단위를 선택한다. 파일당 64 MB, 모델당 삼각형 100만 개까지 지원한다.

새 프로젝트는 `dbf-assembly/2` 형식이다. `objects.sensor`에는 `kind: point_mass`, `mass_kg`, 위치와 형식 호환용 단위 쿼터니언만 들어간다. 센서 메시·표면 삼각형·연결점 오프셋은 저장하지 않는다. 줄은 질점 중심에 자동 연결된다.

이전 파일을 열면 센서 메시를 제거하고 저장된 센서 질량을 질점으로 변환한다. 질량이 없으면 기체·윈치만 복원하고 질점을 추가하도록 안내한다. 원본 파일은 변경하지 않는다. 이전 브라우저 자동 저장은 전환 전에 `legacy-draft-before-point-mass` 키로 별도 보관한다.

수동 저장 사본은 `ui/data/projects`, 해석 입력·공력 출처·로그·결과는 `ui/data/analysis/<실행 ID>`에 보존한다. 과거 형상 센서 해석 결과와 파일의 읽기 호환성은 유지한다. 새 UI에서는 형상 센서 해석을 생성하지 않는다. 기존 파일의 해석 종류는 전개 비행(기존 트림·안정성·시간응답·공력표) 또는 회수(기존 전체 임무)로 전환하며 물성 입력은 유지한다. 과거 전체 임무 실행은 기존 API에서 계속 지원한다.


`ui` 폴더에서:

질점 검증은 실제 저장된 AVL 표로 트림·42자유도 축약 행렬(줄 4분할)·짧은 시간응답을 실행한다. 질점 관성·공력·메시가 계산에 유입되지 않는지, 질량 중복, 전역 좌표 변환, 잘못된 질량·줄 길이 거부를 확인한다. 이는 물리 정확도나 전체 임무 수렴 검증을 대신하지 않는다.


## AVL + flow5 복합 공력표

해석 화면의 **공력 해석기 → AVL + flow5 복합**을 선택한다. 공력표 상세에서 정적 계수·조종 미계수·회전율 미계수의 출처를 각각 고를 수 있다. 기본 조합은 정적 계수와 조종 미계수가 flow5, 회전율 미계수가 AVL이다.

1. 기체를 불러와 부품·질량·CG·공력 면을 정의하고 등록한다. 기존 등록 모델에서 “Xref·Yref·Zref가 CG와 다릅니다”가 나오면 기체 정의에서 새 버전으로 등록한다. 기존 등록 파일은 수정하지 않는다.
2. **실제 해석기로 새 계산**을 고른다. 승강타 범위는 ±10° 안으로 지정한다. 두 해석기는 같은 받음각·옆미끄럼각·승강타 격자와 CG 기준점을 사용한다.
3. 입력 확인 후 실행한다. 선택한 CPU 수를 두 해석기에 나눠 할당한다. 최대 12개이며, 가능한 경우 4개를 남긴다. AVL은 메모리 여유에 따라 작업 수를 더 줄일 수 있다.
4. 결과 카드와 보고서에서 블록별 출처, flow5 계산 속도, 다섯 가지 기울기의 차이를 확인한다. 상대 차이가 20%를 넘으면 점검 문구가 표시된다. 이는 해석기 간 차이이며 실물 정확도나 안전성의 합격 기준이 아니다.
5. 같은 등록 모델·속도·출처 조합이면 저장된 복합 표를 다시 쓸 수 있다. flow5가 들어간 표는 속도가 바뀌면 다시 계산한다.

세 블록의 출처가 모두 같으면 해당 단일 해석기를 선택한다. 회전율을 flow5에서 가져올 때만 기체 정의의 **flow5 종·횡 분리 근사 사용에 동의**가 필요하다. 회전율 출처가 AVL이면 이 확인 없이 복합 계산할 수 있다.

flow5 연결은 VLM2 양력면 범위다. 동체 공력과 상세 후류는 포함하지 않는다. 기존의 추가 항력 입력은 계속 적용한다. 두 해석기의 격자·형상 해시·기준 치수·CG 기준점이 다르면 조합을 거부한다. 서로 다른 저장 표를 보간하거나 외삽해서 맞추는 기능은 넣지 않았다.
