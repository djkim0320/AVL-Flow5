# 계산 모델과 적용 범위

이 문서는 구현한 식, 입력 가정과 검증 경계를 설명한다. 예시 형상은 MIT의 Plane Vanilla를 0.17배로 축소했다. 팀이 제작할 기체의 해석 결과가 아니다.

## 좌표·질량

단위는 m, kg, s, N, rad이다. 입력 조종면과 표시 각도는 deg이다. 관성좌표는 NED, 기체 좌표는 전방·우측·하방(FRD)이다. 쿼터니언은 scalar-first이며 기체에서 관성좌표로 회전한다. 모멘트는 오른손 법칙을 따른다.

기체와 센서는 각각 6자유도로 적분한다. 기체 `mass_kg`에는 센서와 견인선 질량을 넣지 않는다. 견인선은 N개의 동일 질량 셀로 표현하며 각 질량은 μL/N이다. 모든 질량은 수납·전개·회수 중 항상 존재한다. 수납된 줄의 셀은 윈치 위치의 탄성 지지에 연결한다. 전개할 때 셀의 속도를 임의로 바꾸거나 질량을 새로 더하지 않는다.

기체 `cg_m`와 공력 기준점은 AVL 원점에 대한 FRD 좌표다. 기체의 견인점·추력점·출구 치수는 **기체 CG 기준**이다. 센서 접촉점·견인점은 **센서 CG 기준**이다. 두 기준을 혼동하면 견인 모멘트가 달라진다.

## 공력

기체의 CX, CY, CZ, Cl, Cm, Cn 및 p·q·r 미계수는 실제 AVL SB 출력에서 읽는다. 각도·조종면 격자에서 선형 보간하며 p·q·r 항은 각각 pb/(2V), qc/(2V), rb/(2V)를 곱한다. 데이터 범위 밖의 값은 외삽하지 않는다. AVL의 본체축 출력은 `Standard axis orientation`을 확인한다. 조종면 미계수는 출력의 per-degree 값을 사용한다.

q∞=ρV²/2, 힘=q∞S·[CX,CY,CZ], 모멘트=q∞S·[bCl,cCm,bCn]이다. 기준점에서 CG로 모멘트를 이동하고 지정된 profile_cd의 항력을 상대풍 반대 방향으로 더한다. 본체 점성항력과 프로펠러 후류를 AVL이 모두 예측했다고 보지 않는다.

센서는 명시적으로 입력한 CD, 횡력·양력 기울기, 피칭·요잉 모멘트 기울기, 회전 감쇠로 계산한다. 센서 공력계수는 현재 **가정값**이다. 센서가 출구를 통과할 때 공력 노출 비율을 0~1로 변화시키는 근사와 `local_flow_factor`를 사용한다. 큰 받음각·역류·박리 상태에서 센서의 선형 공력식은 검증되지 않았다.

## 견인선과 윈치

각 활성 구간의 장력은 T=max(0, EA/d·(l−l₀)+f·cL/d·l̇)이다. d=max(l₀, 0.1 셀 길이), L은 전체 줄 길이, c는 전체 줄 기준 감쇠계수다. l≤l₀이면 장력은 0이다. 감쇠 활성 비율 f=clip((l−l₀)/(d·ε),0,1)로 느슨한 줄이 팽팽해질 때 감쇠력의 불연속을 줄이며 ε=`damping_engagement_strain`을 입력한다. 이 정규화의 영향도 물성·분할 민감도에 포함해야 한다. 수납 지지의 강성·감쇠 입력값은 전체 값이며 셀 수로 나눈다.

센서 쪽 첫 구간은 반 셀 길이이며, 윈치 쪽 마지막 부분 구간만 풀고 감는 길이에 따라 변한다. 전개 완료 시 양 끝이 반 셀 길이가 된다. 이 구성은 실제 연속 줄의 질량 유입 경계를 정확히 푼 ALE 모델이 아니다. 물질 셀 질량과 속도는 유지하지만 활성 전환에서 탄성·구속 에너지가 바뀔 수 있다. 현재 점성항은 끝점 간 거리 변화율을 사용하며 줄 유입의 연속체 변형률 이력을 완전히 해석하지 않는다.

셀은 센서 쪽에서 윈치 쪽 순서로 활성화된다. 시뮬레이션은 셀 활성 전환 시각에서 적분을 끊고 다시 시작한다. 이 방식은 질량·속도 재매핑 대신 고정된 물질 셀의 구속을 바꾸는 방법이다. 윈치 내부의 실제 줄 감김 형상·마찰·회전관성은 해석하지 않는다.

`stowed`와 `aircraft_only`에서는 줄 길이를 수납 길이로 고정하고 전개·회수 이력을 실행하지 않는다. 고정 길이 견인은 `deployed`, 시간에 따라 줄을 풀고 감는 과정은 `mission`으로 구분한다.

분포 항력은 줄의 국소 접선·법선 방향으로 나누어 계산한다. 케이블 휨·비틀림, 줄 자체 접촉, 매듭·걸림·파단은 포함하지 않는다. 윈치는 지정한 길이 이력을 따라가는 이상적 속도 구동원이다. 요구 토크와 한계 초과를 표시하며, 실제 토크 부족으로 속도가 떨어지는 제어 모델은 아직 없다. 따라서 토크 초과가 있는 회수 결과는 실행 가능한 경로로 판단하지 않는다.

`winch.limit_power_W`를 지정하면 요구 기계 동력의 절댓값도 비교한다. 생략하거나 null로 두면 출력 한계의 합격 판정을 하지 않는다. 회수 구동과 전개 제동의 서로 다른 모터 특성은 이 단일 한계 모델에 포함하지 않는다.

기체·센서·케이블에 동일 크기의 반대 방향 힘을 적용하고 작용점의 모멘트를 반영한다. 줄을 감는 요구 기계 동력은 −T·L̇이며, +는 회수 시 공급 동력, −는 전개 시 제동·에너지 회수를 뜻한다.

## 내부 이동·접촉·포획

후방 문은 회전축이 기체 y축인 유한 두께의 직육면체로 단순화한다. 바닥·천장·측면도 두께가 있는 유한 판으로 계산해 출구 모서리와 뒷면을 구분한다. 센서 몸체 양끝과 핀 끝의 구형 접촉 표본점으로 각 판과 접촉을 계산한다. 문 각도 이력의 표면 속도를 접촉 상대속도에 반영한다. 기체의 전면 전체나 복잡한 CAD 메시끼리의 충돌을 계산하는 기능은 아니다.

법선 접촉력은 max(0,k·침투량−c·법선 상대속도)이다. 마찰은 작은 속도에서 정규화한 Coulomb 근사다. 수납 지지와 포획 장치는 선형·회전 스프링 감쇠기로 표현한다. 포획 조건은 위치·상대속도·상대자세를 모두 만족해야 하며 속도를 강제로 0으로 바꾸지 않는다. `captured`는 포획 구속의 작동 여부이며, 이후 하중·침투·유지 여부는 별도 검토가 필요하다.

출력에서 `contact_N`은 벽·문 접촉 법선력 합, `latch_N`은 수납·포획 지지력, `capture_N`은 포획 작동 후의 지지력이다. 적분한 `contact_impulse_Ns`는 접촉 법선력 합의 시간 적분이며, 여러 접촉이 겹치면 단일 충돌의 벡터 충격량과 다르다. 허용 침투량을 넘으면 해당 접촉 근사는 신뢰하지 않는다.

포획이 걸리는 순간의 직전·직후 힘을 보존하기 위해 같은 시각의 행이 두 개 있을 수 있다. 두 행의 위치·속도는 같다. 이 구간의 시간 차이가 0이므로 CSV로 속도나 가속도를 차분할 때 사건 중복 시각을 구분해야 한다.

## 트림·안정성

트림은 무풍·대칭·직선 수평비행을 대상으로 한다. 수납 트림은 전체 중량과 질량 위치를 반영한 준정적 트림이며 탄성 지지의 초기 처짐까지 평형화하지는 않는다. 전개 트림은 센서 자세와 모든 줄 구간의 정적 평형까지 푼다. 좌우로 치우친 견인점의 비대칭 트림은 명시적으로 거부한다.

기체 단독·수납 트림도 힘과 모멘트의 세 축을 모두 검사한다. 세로 방향 평형만 맞고 롤·요 가속도가 남으면 트림 성공으로 처리하지 않는다. 전개 트림의 케이블 국소 유속은 시간응답 계산과 같은 설정을 사용한다. 고유값을 계산하기 전에는 입력 상태의 가속도와 회전율을 검사해 평형이 아닌 상태를 거부한다.

고정 길이·비접촉 평형의 Jacobian에서 고유값을 계산한다. 쿼터니언 크기 자유도는 제외하고 작은 회전벡터를 사용한다. 0 근처의 운동학적 모드는 구분한다. 실제 고유모드 이름은 고유벡터 분석 없이 자동으로 단정하지 않는다. 전개·접촉·포획 중에는 이 고유값을 안정성 판정으로 사용하지 않는다.

## 수치 적분과 에너지 경계

Radau 적분을 길이 이력의 꺾임·물질 셀 전환·고정 해제·포획에서 나누어 실행한다. 수납 셀의 선형 미분은 해석식으로 계산하고 나머지는 구조를 이용한 차분으로 계산한다. 차분 Jacobian은 독립적인 방향 차분 검사와 비교한다. 기체 또는 센서의 CG가 지면에 도달하면 적분을 중단한다. 착륙장치와 지면 충돌은 해석하지 않는다.

조종 입력 이력의 꺾임과 돌풍의 시작·끝에서도 적분을 나눈다. 시작 상태가 이미 지면에 도달한 경우 시간을 진행하지 않고 중단한다. 여러 설계안을 병렬로 계산할 때는 각 설계안 내부의 Jacobian 병렬 풀을 끄고 실제 작업자 설정을 기록한다.

전체 질량은 항상 일정하다. 별도 외력이 없는 시험에서 선운동량과 각운동량을 확인한다. 그러나 이것만으로 윈치 구동·수납 셀 활성 전환·마찰·열을 포함한 전체 에너지 보존을 입증하지는 않는다. 출력의 `winch_work_J`는 −T·L̇의 적분인 준정적 릴 일 추정값이며 완전한 전기/기계 에너지 수지가 아니다. 이 경계는 실물 검증 전 남은 개발 항목이다.

`kinetic_work_audit`는 수납·전개된 줄의 운동에너지를 모두 포함해 운동에너지 변화와 합력·모멘트의 일을 비교한다. 이는 적분·출력 시간 간격 및 질량 기록의 일관성 검사다. 내부 탄성 저장·마찰열·구동원의 일을 각각 분리한 열역학적 에너지 보존 검사로 해석하면 안 된다.

이 검사는 결과에 저장된 실제 트림 명령과 포획 시각을 사용한다. `summary.json`에 `trim`이 없는 과거 결과는 명령을 새로 추정하지 않고 오류를 낸다. 기존 기록을 검사하려면 해당 실행의 실제 명령 기록을 먼저 확보해야 한다.

## 복합 공력표 · 구현 기준

`aero.backend: hybrid`와 다음 조합을 사용한다. 빌드 진입점은 기존 `build_aero_database(config, output, workers)`이며, 별도 호출은 `dbf_stability.hybrid.compose_tables(sources, composition, output)`이다. `sources`에는 `avl`, `flow5` 키로 원본 npz 경로나 `AeroDatabase`를 전달한다.

```yaml
aero:
  backend: hybrid
  hybrid:
    coeff: flow5
    controls: flow5
    rates: avl
```

- `coeff`는 FRD `[CX,CY,CZ,Cl,Cm,Cn]`, `controls`는 도당 에일러론·러더 미계수, `rates`는 `[pb/2V,qc/2V,rb/2V]`당 미계수다. 승강타 효과는 `coeff`의 승강타 격자에 들어간다.
- 세 출처가 같으면 단일 해석기를 요구한다. `rates: flow5`에는 `rate_derivative_closure: classical_longitudinal_lateral`이 필요하다. AVL 회전율을 쓸 때 flow5 하위 실행에만 이 설정을 주고, 그 회전율 블록은 버린다. 원래 설정은 바꾸지 않는다.
- 두 원본의 형상·참조 파일 해시와 격자는 같아야 한다. 기준 면적·시위·날개폭은 두 값 중 큰 값 기준 상대 1e-5 이내, 기준점은 절대 1e-9 m 이내여야 한다. AVL 원본 파일과 실제 실행 폴더의 `plane.avl` 헤더를 모두 CG와 대조한다.
- 새 UI 등록은 CG를 AVL 기준점으로 기록한다. 기존 단일 해석용 등록 파일과 표는 그대로 보존한다. 기존 운동 모델은 공력 블록을 합한 힘·모멘트에 기준점 이동을 적용하므로, 정적 모멘트만 이동한다고 해석해서는 안 된다. 회전 중심까지 맞추기 위해 복합 계산은 두 원본 모두 CG에서 계산하도록 제한한다.
- 두 원본은 출력 폴더 아래 `avl/`, `flow5/`에 보존한다. 원본 npz 해시, 실행 경로·버전, 선택·제외 블록, 계산 속도, 비교 결과가 최종 메타데이터에 들어간다. 기존 출력 파일과 하위 실행 폴더가 있으면 덮어쓰지 않고 오류를 낸다.
- `consistency_report`는 각 각도의 0°에 가장 가까운 점에서 CLα, Cmα, CYβ, Clβ, Cnβ를 비교한다. 내부점에서는 양쪽 이웃의 차분, 경계에서는 한쪽 차분을 쓴다. 사용한 점과 간격을 기록한다. 상대 차이는 `abs(a-b)/max(abs(a),abs(b))`다. 두 기울기가 모두 1e-10 이하면 상대값은 null이고 절대 차이를 기록한다. 상대 20% 초과는 경고다.
- flow5 속도는 `flow5_speed_m_s`로 저장한다. 새 flow5·복합 표는 현재 비행 속도와 다르면 재사용을 거부한다. 오래된 단일 flow5 표의 속도 검사는 UI 실행 요청 기록을 사용한다.
- 작업자 수 1은 순차 실행, 2 이상은 두 해석기에 분배한다. 각 flow5 작업의 스레드는 1개다. AVL의 기존 메모리 예산 검사도 유지한다.

두 해석기의 차이가 작아도 실제 기체의 정확도를 입증하지 않는다. 동체·문·후류·점성 효과의 추가 검증과 수치 수렴 검사는 별도다. 서로 다른 격자·기준점의 표를 보간하거나 이동해 결합하는 선택 항목 B5는 구현하지 않았다.
