# 코드 구조·연산 일관성 점검 — 2026-09-22

공력 입력부터 트림·운동 적분·접촉·검증·병렬 실행, 3D 배치 편집기까지 검토하고 재현한 오류를 수정했다. 최종 자동 검사는 **184건 통과, 실패·건너뜀 0건**이다. 이는 코드 회귀검사 결과이며 기체 안전성이나 접촉력의 실물 정확도를 입증하지 않는다.

## 점검 범위

`src/dbf_stability`의 설정·AVL·flow5 연동, 결합 운동과 좌표·질량 처리, 트림·고유값, 적분과 접촉 사건, 체크포인트와 에너지 검사, 병렬 처리, 기존 시험을 읽었다. `ui`의 모델 반입, 좌표 변환, 줄 연결점, 저장·복원, 서버 입력 검증도 확인했다. 다른 프로젝트 파일은 검토하지 않았다.

모든 함수를 다시 설계하거나 모든 임무를 재계산한 것은 아니다. 확인된 오류에는 회귀검사를 추가했고, 기존 물리 근사의 한계는 별도로 남겼다.

## 수정한 문제

| 문제 | 영향과 수정 |
|---|---|
| 수납 상태에서도 임무의 윈치 이력이 실행됨 | 문이 닫히고 센서가 고정된 상태에서 줄 길이가 바뀌었다. `stowed`·`aircraft_only`에서는 수납 길이와 전개 속도 0을 유지한다. |
| 트림이 세로 방향 힘·모멘트만 검사함 | 추력점을 옆으로 50mm 옮긴 재현 사례에서 약 −0.244rad/s² 요 가속도가 남아도 성공했다. 힘·모멘트의 모든 축을 검사하며, 지원하지 않는 평형은 실패로 처리한다. |
| 견인 평형과 시간응답의 케이블 유속이 다름 | 국소 유속 비율을 켠 경우 서로 다른 항력으로 계산했다. 완전 전개 트림에도 같은 유속 비율을 적용한다. |
| 평형이 아닌 입력으로 고유값 계산 가능 | 가속도·회전율을 확인하고 정지 평형 조건에 맞지 않으면 중단한다. 활성 메시 접촉도 거부한다. |
| 다른 기체·해석기의 공력표를 사용할 수 있음 | 주 공력 형상 파일 해시와 AVL/flow5 선택을 검사한다. 실제로 R2·R3 시험에 H1 표가, AVL 임무 시험에 flow5 표가 섞여 있었다. 일치하는 실제 해석 결과로 시험 자료를 고쳤다. |
| 하위 폴더의 설정을 다시 읽을 때 기준 경로가 잘못됨 | 저장된 실행 설정의 상대 경로가 실행 폴더를 기준으로 해석됐다. 명시한 `root`, 저장된 기준 경로, 프로젝트 루트 순으로 결정한다. |
| 비정상 입력이 계산에 진입함 | NaN·Inf, 잘못된 벡터·격자·입력 이력, 유효하지 않은 크기·시간·쿼터니언, 손상된 공력표를 앞단에서 거부한다. |
| 사건 경계와 실패 분류가 불완전함 | 조종 입력 꺾임과 돌풍 경계에서 적분을 나누고, 처음부터 지면에 닿은 상태는 진행하지 않는다. 조종 범위 이탈을 일반 수치 실패와 구분한다. |
| 에너지 검사에서 다른 트림을 다시 계산함 | 새 결과에 실제 트림 명령을 보존하고 이를 재사용한다. 포획 시각도 복원해 문 연동 상태를 맞춘다. 명령 기록이 없는 과거 결과는 추정하지 않는다. |
| 설계안 병렬 풀 안에서 다시 병렬 풀 실행 | 작업자 수가 곱으로 늘어날 수 있었다. 여러 설계안을 병렬로 돌릴 때 내부 Jacobian은 직렬로 두고 실행 정책을 기록한다. |
| 결과 덮어쓰기·접촉 자원 정리 | 기존 AVL 공력 파일과 설계안 결과 폴더를 덮어쓰지 않는다. 트림·고유값·진단·에너지 계산에서 오류가 나도 모델 자원을 닫는다. |
| STEP 크기가 단위 선택에 따라 1,000배 달라짐 | 변환기가 반환한 mm를 자동 적용한다. STL·GLB 단위 선택과 분리했다. |
| UI에서 한 좌표를 수정하면 다른 좌표까지 반올림됨 | 변경한 축만 반영하고 나머지 위치·회전의 정밀도를 유지한다. 빈 좌표 입력은 0으로 바꾸지 않는다. |
| 기체 이동·회전 후 윈치가 원래 자리에 생성됨 | 기준 윈치를 현재 기체의 위치·회전으로 변환해 생성한다. |
| 저장된 모델의 ID가 같으면 과거 형상이 남음 | 파일을 열 때 실제 메시를 새로 설치하고 편집 세션의 자산 ID를 새로 부여한다. 형상 교체의 되돌리기·다시 실행도 유지한다. |
| 로딩 중 조작과 서버 입력 검사 누락 | 로딩 중 단축키·선택·속성 변경을 제한한다. 잘못된 표면 인덱스, 빈 연결점, 누락된 원점 정보 등을 저장 전에 거부한다. |

공력 일치 검사는 주 형상 파일과 해석기 종류를 대상으로 한다. 별도 에어포일 파일 등 모든 외부 의존 파일의 변경까지 탐지하는 검사는 아니다. 그런 파일을 수정했을 때도 공력표를 다시 만들어야 한다.

## 실제 해석과 시험 기록

- R2 형상에 대해 **AVL 3.52의 315개 조건을 실제로 다시 계산**했다. 8개 작업자를 논리 프로세서 0–11 범위에서 실행했다. 새 공력표는 `outputs/refined_r2_aero_database.npz`, 원본 입력·출력은 `outputs/avl_runs_0b28fd3d`에 있다.
- AVL 연동 회귀검사는 별도의 8개 조건을 실제 실행한다. 가짜 공력값으로 성공 판정을 대신하지 않았다.
- 계산부 고유 시험 173건, UI Python 검사 7건, UI JavaScript 검사 4건이 통과했다. 묶음 사이 중복 실행은 총계에서 제외했다. Python 시험을 세 그룹으로 나누어 병렬 실행했으며 BLAS/OMP 내부 스레드는 1개로 제한했다.
- 최종 JUnit 기록은 `outputs/code_audit_20260922/final_physics.xml`, `final_contact.xml`, `final_geometry.xml`, `regression_final.xml`이다. 요약은 같은 폴더의 `test_summary.json`에 있다.
- flow5 연결·출력 변환 회귀검사는 기존 실제 해석 자료를 사용했다. 이번 점검에서 flow5의 전체 공력표를 새로 계산하지는 않았다.

브라우저에서도 사용자 작업과 분리된 로컬 시험 화면으로 다음을 확인했다.

1. H1 기체를 X 방향 100mm 이동하고 Z축으로 90° 회전한 뒤 윈치를 추가했다. 윈치 위치는 약 `[100, −293.42, 38.82] mm`, 회전 Z는 90°로 생성됐다.
2. 파일 단위를 m로 선택한 채 실제 `sensor_body.step`을 불러왔다. 외곽 크기는 올바르게 `120 × 28 × 28 mm`로 표시됐다.
3. 같은 자산 ID를 유지한 채 센서 메시를 두 배로 수정한 검증용 배치 파일을 열었다. `240 × 56 × 56 mm`로 바뀌었고, 되돌리기를 누르면 원래 크기로 복원됐다. 다시 실행하면 두 배 크기가 돌아왔다. 이 조작 중 브라우저 오류·경고 기록은 없었다.

수정 전 소스 사본은 `outputs/code_audit_20260922/source_before.zip`, 변경 비교는 같은 폴더의 `source_changes.diff`다. 새 시험 코드와 추가 파일은 해당 소스·시험 폴더에 있다.

## 남은 모델 한계와 기존 결과

견인선의 물질 셀 활성 전환은 연속체의 유입·유출을 완전히 푸는 방식이 아니다. 전체 질량·운동량 검사를 통과해도 탄성 에너지·윈치 구동·마찰열을 포함한 에너지 보존이 입증되는 것은 아니다. 윈치도 지정 속도를 따르며 토크 부족에 따른 실제 감속 동역학은 없다.

접촉·후류·센서 공력에는 아직 가정값이 있다. 10→20→40구간과 시간 간격을 줄이는 수렴 검사, 실험값과의 비교는 계속 필요하다. UI의 새 CAD 배치를 공력·질량·접촉 모델로 자동 연결하는 기능도 아직 구현되지 않았다. 이 점검에서는 계산이 끝났다는 이유로 `analysis_ready`나 수렴 판정을 참으로 바꾸지 않았다.

기존 75초 전체 임무와 영상은 당시 코드의 기록으로 보존했다. **이번 점검 후 전체 임무를 다시 계산한 것은 아니다.** 수정 전 체크포인트는 코드 해시가 달라 재개 검사를 통과하지 않을 수 있으며, 검사를 우회해 같은 실행으로 이어 붙이면 안 된다. 다음 전체 임무 결과는 수정된 코드와 일치하는 공력표로 별도 실행해야 한다.
