# 다중 STEP 조립체 검증

2026-09-28

파일 선택과 드래그 앤 드롭의 기본 동작을 기존 기체에 추가하는 방식으로 바꿨다. 파일마다 선택·이동·회전·고정·제거할 수 있고, 별도 교체 버튼으로 새 기체를 시작한다. 기존 단일 파일 프로젝트도 읽는다.

## 저장과 해석 연결

`objects.aircraft.components`에 파일 이름·출처·소속 부품 번호·편집 중심·회전·고정 상태를 저장한다. `parts[].positions`는 배치를 반영한 기체 좌표계의 최종 꼭짓점이다. 해석·단면 추출·형상 서명·결과 재생에서는 부품 변환을 다시 적용하지 않는다. 편집기의 하위 그룹만 역변환한 표시용 꼭짓점을 사용한다.

부품 배치가 바뀌면 해당 공력 면의 단면을 비우고 검토 상태를 해제한다. 전체 물성 모드는 CG·관성을 다시 입력하며, 파일 추가·제거 시 질량도 다시 입력한다. 부품별 모드는 기존 CG와 관성 행렬을 강체 변환하고, 새 부품의 물성은 미입력으로 둔다. 삭제 후에는 남은 부품 번호와 공력 면 연결을 재배열한다. 기존 공력표는 다른 형상에 재사용할 수 없다.

## 확인한 범위

- JavaScript 검사 42개 통과: 원점 유지, 개별 강체 변환, 고정 상태, 잘못된 메타데이터 거부, 제거·번호 재배열, CG·관성 변환, 물성·단면 갱신, 기체 방향 보정, 병렬 불러오기 실패 처리 및 기존 UI 검사.
- Python UI 검사 45개 통과: 저장 형식, 형상 서명, 해석 입력, 기체 정의와 기존 연결 검사 포함.
- 실제 AVL 통합 검사 1개 통과: 다중 파일 메타데이터가 있는 시험 형상 등록 → 새 AVL 공력표 병렬 계산 → 트림·고유값 → 회수·연속 비행 → 제어 응답·재생 데이터 생성. 공력 출력을 대체하지 않았다. 이 시험은 해석 경로 검증이며 N3 실기체 성능 검증이 아니다.
- 브라우저에서 실제 N3 STEP을 본체 34솔리드, 고정 꼬리날개 4솔리드, 승강타 2솔리드로 나눠 불러왔다. 두 파일을 동시에 불러온 다음 윈치·질점을 추가하고, 세 번째 파일을 추가해 기존 배치가 유지됨을 확인했다.
- 승강타 파일의 위치·회전 입력, 화면 드래그, 고정, 저장 후 새로고침 복원, 제거·되돌리기를 확인했다. 정상 STEP과 손상된 STEP을 함께 넣으면 두 파일 모두 추가되지 않고 기존 조립체가 유지된다.
- 분리된 고정 꼬리날개와 승강타를 함께 선택해 CAD 단면을 추출했다. Y=0.05/0.30 m에서 시위는 약 0.209973/0.158908 m였고, 조종면 `elevator`, 힌지 x/c=0.7을 저장했다. 저장된 파일에서 3개 파일·40개 솔리드·부품 연결·조종면·단면을 다시 검사했다.

N3 조립 데모는 배치와 단면 추출만 확인한 미완성 기체 정의다. 질량·관성·전체 양력면을 채워 등록하기 전에는 이 데모로 해석을 실행할 수 없다. 개발 PC의 `ui/design/multi-step-20260928`에 STEP 세 파일, 배치 JSON, 검증 화면을 보관하며 생성 파일은 Git에 포함하지 않는다.

## 조종면 설정의 한계

승강타 파일은 독립적으로 배치할 수 있지만 파일 이름으로 조종면을 자동 추정하지 않는다. 사용자가 부품 역할과 공력 면의 조종면 종류·힌지 x/c를 지정해야 한다. 부분 조종면은 span 구간을 나눠 정의한다. CAD 힌지 구속, 서보 운동, 재생 중 조종면 메시 애니메이션은 이번 변경에 포함하지 않는다.
