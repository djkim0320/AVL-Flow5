# 범용 기체 정의 UI

기체 파일을 불러온 뒤 **기체 정의 · 부품 / CG / 공력 면**을 누른다. 기체 이름이나 S27의 부품 번호에 따라 해석을 바꾸지 않는다. S27은 CAD 선택·좌표 편집·단면 추출을 확인하는 테스트 모델이다.

## 입력 순서

1. **부품**: 3D에서 클릭하거나 목록에서 선택한다. Shift로 여러 부품을 고르고 주익, 꼬리날개, 동체, 문, 장비 등의 역할을 적용한다. 공력에서 제외해도 질량 합산에서는 제외되지 않는다.
2. **질량·CG**: 전체 기체의 값 또는 부품별 값을 입력한다. CG는 CAD 원점 기준 mm로 입력하거나 분홍색 표시의 축을 드래그한다. 화면에서 기체를 이동·회전해도 저장되는 CG는 기체의 로컬 좌표다. **형상 중앙에 CG 초안 배치**는 편집 시작점을 제공하며 실제 CG를 추정하지 않는다.
3. **관성**: 각 CG 기준의 관성 행렬을 기체축으로 입력한다. 부품별 모드에서는 질량 가중 CG와 평행축 정리로 전체 관성을 합산한다. CAD가 관성곱을 내보내면 행렬 성분과 부호를 확인한다. 배터리·모터·윈치는 기체 질량에 포함하고, 별도로 계산하는 줄·센서 질점은 제외한다.
4. **공력 면**: 선택한 부품을 면으로 추가하고 단면 절단 축과 위치를 정한다. 실제 CAD 메시를 절단해 앞전·시위·설치각·에어포일 좌표를 만든다. 끝면, 내부 구조물, 서로 떨어진 외피에서는 추출이 거부될 수 있다. 추출 범위에 빠진 루트·팁을 확인하고 단면을 수정한다. 직접 입력한 NACA 4자리 또는 DAT도 사용할 수 있다.
5. **조종면·추진**: 조종면 종류와 힌지, 기준 면적·시위·날개폭, 추가 항력계수, 최대 추력과 작용점을 입력한다. 조종면은 정의한 면의 전체 span에 적용된다. 하나의 CAD 부품을 여러 공력 구간으로 나눌 수 있지만 구간이 겹치면 등록을 거부한다. 현재 견인 트림에는 승강타가 필요하다.
6. 출처와 가정을 적고 **해석 입력 확인**을 누른다. 단면·물성·좌표 확인 후 **해석 모델 등록**으로 새 버전을 만든다. 등록된 모델이 해석 화면에 선택된다. 윈치·질점·줄과 비행 조건을 확인한 뒤 실제 AVL 또는 flow5 공력 계산을 실행한다.

입력을 모두 마치지 않아도 프로젝트를 저장할 수 있다. 부품 역할·CG·단면을 수정하면 기존 등록 모델과의 연결이 해제되며 새 버전 등록이 필요하다. 정의 화면을 열어 보기만 하거나 아무 값도 입력하지 않은 빈 정의는 수정으로 보지 않으며, 기존 모델 연결을 유지한다. 정의의 좌표는 현재 CAD 방향 기준이므로, 기체 방향(해석 기준 +X 앞)은 정의를 입력하기 전에 배치 화면의 **해석 기준 방향**에서 맞춘다. 해석 화면에서 기체 질량·관성을 따로 바꾸어 등록값과 어긋나게 만들 수 없다.

## 지원 범위

- 기체 정의는 SI·FRD 좌표로 저장한다. 파일을 불러올 때 원본 축 방향을 지정해야 하며, 화면에서 보이는 모양만으로 앞뒤를 자동 판정하지 않는다.
- AVL 입력은 사용자 정의 양력면과 실제 에어포일 좌표로 생성한다. 동체·문·장비의 압력 분포는 생성하지 않으며 추가 항력은 명시적인 입력값이다.
- flow5 연결은 기존 VLM2 변환기를 사용한다. 현재 변환기는 좌우 대칭 수평면과 수직면을 지원하며, 출력되지 않는 종·횡 교차 회전율 미계수의 근사를 사용하려면 UI에서 이를 확인해야 한다. 비대칭 수평면·기울어진 수직면은 이 자동 변환 경로에서 거부한다.
- 현재 결합 트림은 좌우 대칭 견인 조건을 지원한다. 임의의 비대칭 형상·측방 윈치 위치에 대한 6축 트림은 추가 개발이 필요하다.
- 전개 비행과 회수는 질점·줄 모델이다. CAD 접촉·포획·문 닫힘을 계산하지 않는다. 부품 역할 지정으로 접촉 해석이 활성화되는 것은 아니다.
- AVL 병렬 계산은 요청한 작업자 수를 상한으로 사용한다. 번들 실행파일의 메모리 사용을 고려해 작업당 2 GiB와 여유 1 GiB를 기준으로 동시 실행 수를 줄인다. 실제 요청값·적용값은 원본 실행 폴더의 `execution.json`과 공력표 메타데이터에 남는다. 이 값은 스케줄링 추정치이며 다른 프로그램의 메모리 점유 변화까지 보장하지는 않는다.

## 이번 검증

S27 STEP의 76개 부품을 불러온 상태에서 주익 선택·역할 지정, CG 축 드래그와 숫자 입력, 실제 주익 메시의 두 단면 추출, 저장 후 새로고침 복원을 확인했다. 시험용 5 kg과 CG (800, 0, -418.5) mm는 측정값이 아니다. S27의 관성·추진·전체 양력면은 미완성 상태로 남겼다.

별도의 명시적 검증 기체 정의로 등록 → 27개 실제 AVL 3.52 조건 → 질점·줄 결합 평형 → 78개 모드 → 0.2초 시간응답 경로를 실행했다. 평형 잔차는 약 2.21×10⁻⁸이며 시간응답 상태는 completed였다. 12개 작업자를 요청했고 가용 메모리에 따라 3개를 동시에 실행했다. 이는 프로그램 연결 확인이며 S27 예측, 장시간 안정성, 수치 수렴 또는 시험 검증 결과가 아니다. 이번 변경에서 flow5는 생성 입력을 읽는 경로를 검사했으며 새 정의의 실제 flow5 실행은 아직 검증하지 않았다.

보관 자료는 `outputs/generic_aircraft_ui_20260928/`에 있다.

- `S27_ui_test_draft.dbf.json`: 사용 중이던 S27 배치와 UI 시험 초안. 원본 배치 사본은 `outputs/run_blocker_20260928/S27_user_before.dbf.json`에 보존했다.
- `analytic_validation_project.json`, `integration_result.json`: 실제 해석 연결 검증의 입력과 요약.
- `generated_avl_database.npz`, `avl_runs_*`: 실제 공력표와 실행 원본. 첫 병렬 실행의 메모리 부족 기록도 보존했다.
- `flight/`: 짧은 시간응답의 입력·시계열·상태.

관련 Python 검사 37개와 하위 검사 4개, JavaScript 검사 23개가 통과했다. 실행 재현 스크립트는 `scripts/verify_generic_aircraft.py`다. 기존 결과 파일을 덮어쓰지 않으므로 다시 실행할 때는 `--output`으로 새 결과 폴더를 지정한다.
