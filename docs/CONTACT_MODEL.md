# H1 동체·가이드 관통 수정

이전 `20260917_031449/mission` 궤적은 물리적으로 무효다. 와이어의 충돌 반력이 없었고, 동체·윈치 등이 센서 충돌 대상에서 빠져 있었다. 결과와 CAD 교차 증거는 그대로 보존한다.

## 계산에 반영한 변경

- H1 부품별 STL을 계산에 직접 연결한다. 동체는 내부 공간과 절개부가 있는 비볼록 메시로 유지한다. 출구 프레임은 같은 빈 구멍을 가진 네 개의 상자로 분해한다. 전체를 하나의 볼록 덩어리로 바꾸지 않는다.
- 센서 몸체와 네 핀의 전체 형상을 검사한다. 원통 몸체는 CAD의 볼록 표면 메시를 사용하고 핀은 해당 CAD 치수의 상자로 계산한다.
- 모든 노출 와이어 구간을 반경이 있는 캡슐로 검사한다. 두 끝점이 벽 밖에 있어도 그 사이가 벽을 가로지르면 검출한다. 평평한 가이드와 문에는 구간–상자 거리식을 사용한다.
- 접촉력은 센서 또는 와이어 양 끝에 적용하고 같은 작용점의 반력을 기체에 돌려준다. 힘과 모멘트 수지가 맞는지 별도 검사한다.
- 센서의 평면·모서리 접촉에는 여러 접촉점으로 힘을 나눈다. 핀은 상자 형상의 전체 꼭짓점·모서리를, 원통 몸체는 실제 표면 메시의 꼭짓점–면 및 모서리–모서리 쌍을 사용한다. 한 점의 최근접 위치가 두 모서리 사이를 오가며 전체 반력의 작용점이 바뀌던 문제를 수정했다. 같은 평면을 나눈 삼각형의 내부 대각선은 몸체 모서리에서 제외한다.

와이어는 구간 내부의 접촉을 끝점 접촉으로 갑자기 바꾸지 않는다. 구간 좌표를 `s`라고 할 때 `거리² + ε²(s−0.5)²`를 최소화하는 접촉점을 사용하고, 이 거리 함수의 기울기로 양 끝에 힘을 배분한다. `ε=0.16mm`는 입력에 기록한 접촉점 계산용 수치 설정이다. 감쇠에는 같은 기울기로 구한 접근 속도를 사용한다. 관통 검사는 이 완화 거리 대신 원래 형상의 정확한 최소 거리를 사용한다. 이전 방식은 끝점이 접촉 여유에 들어올 때 구간 내부 접촉력이 사라져, 0.00002mm 위치 변화에 약 6.26N의 반력 차이가 생겼다. 이 경계 상황을 회귀 검사에 추가했다.

공력과 운동 적분은 기존 AVL 데이터와 SciPy Radau를 사용한다. Bullet은 거리·법선 등 형상 조회만 맡는다. 이 용법은 [Bullet 공식 조회 예제](https://github.com/bulletphysics/bullet3/blob/master/examples/pybullet/examples/getClosestPoints.py)를 따른다. 적분 단계별 처리는 [SciPy Radau](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.Radau.html)와 [OdeSolution](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.OdeSolution.html)의 공개 인터페이스를 사용한다.

## 도어 회전축과 문판 위치

`bay.door_hinge_offset_m`은 기존 출구 하단 중심에서 회전축까지의 이동량이고, `bay.door_closed_offset_m`은 닫힌 문판의 이동량이다. 두 값 모두 전방·우측·하방(FRD)의 미터 단위 벡터이며, 생략하면 기존 배치를 유지한다. 문 개방각은 닫힘 0°에서 기체 y축 양의 방향으로 증가한다.

기존 100° 도어는 센서뿐 아니라 프레임·가이드 바닥과도 일부 겹쳤다. 힌지만 뒤·아래로 3mm 옮긴 첫 수정안은 열리기 시작하는 1~2°에서 프레임 상단과 겹쳐 채택하지 않았다. 문판도 뒤로 3mm 옮겨 프레임 바깥면에 두는 수정안을 별도 입력으로 만들었다. `h1_door_100.yaml`, `h1_door_140.yaml`, `h1_door_160.yaml`이 이 배치를 사용한다.

`door.py`의 동일한 형상 변환을 접촉 메시, 거리 계산용 상자, 도어 표면 속도와 이동 상한, 재생 화면, STEP 궤적 검사에 적용한다. 원래 100° STL·STEP 파일은 변경하지 않는다. 새 배치의 도어–고정 기체 CAD 검사는 `audit_door_swing.py`, STEP 조립체 출력은 `export_door_variant.py`로 수행한다. 센서·와이어의 궤적 검사와 도어 자체의 회전 간섭 검사는 서로 별개다.

이 수정안은 지정 각도로 움직이는 이상적인 힌지다. 힌지 브래킷, 구동장치, 씰의 상세 구조와 구동 토크는 포함하지 않는다. 문 움직임에 따른 독립적인 관성 반력이나 개방각별 후류도 추가하지 않았다. 도어 근처의 센서·줄 접촉 반력은 기존과 같이 기체에 전달한다.

## 출구 치수와 실제 형상의 연결

출구 높이를 바꿀 때는 YAML 치수뿐 아니라 천장·측벽·프레임·문판·동체 절개부를 함께 재생성한다. `build_opening_variants.py`는 H1 시험 폴더 안에 복사된 STEP만 사용하며 원본 모델링 프로젝트를 읽지 않는다. 각 변경안의 `geometry_variants/opening_*/cad`에 STEP, `meshes`에 실제 계산·표시용 STL·GLB를 저장한다.

접촉 계산은 `collision.mesh_directory`의 STL을 읽고, 재생은 같은 폴더의 GLB를 읽는다. 독립 CAD 검사는 그 형상 폴더와 짝을 이루는 `cad` 폴더를 사용한다. 지정한 형상이 없으면 오류로 중단하며 원래 56mm CAD로 대체하지 않는다. 70mm 안은 바닥을 유지하고 상단을 14mm 높였으며, 기체 질량·CG·관성은 형상 영향 비교를 위해 기존 가정값을 유지했다.

80mm 안은 커진 문판이 열리는 과정에서 꼬리날개와 겹쳐 운동 계산에서 제외했다. 도어의 고정 부품 간섭 검사를 통과해야 `run_opening_study.py`가 운동 계산을 시작한다. 개구부를 키운 결과와 포획 여부는 별도 실제 궤적으로 판단한다.

## 관통 방지와 계산 중단

표면에서 0.8mm 이내에 가까워지면 반발력이 작용한다. 이는 실측 재료 변형량이 아닌 수치적 접촉 여유다. 가까워질수록 반발력이 커지는 함수를 사용하며, 입력한 강성 20,000N/m과 감쇠 8N·s/m 역시 강체 접촉 근사를 위한 수치 설정이다. 충격 하중을 실물 예측값으로 검증한 것이 아니다.

한 단계의 상대 표면 이동을 현재 최소 거리의 40% 이하로 제한한다. 접촉 여유 안에서는 추가로 0.2mm, 그 밖에서는 2mm 상한을 적용한다. 거리 조회는 10mm까지 수행하며, 그 범위에 물체가 없으면 10mm를 보수적인 거리 하한으로 쓴다. 비교 계산은 두 이동 상한을 각각 절반으로 줄인다. Radau의 실제 보간 곡선을 베지어 제어점으로 바꿔 병진·회전 이동의 상한을 검사하고, 초과하면 이전 상태부터 더 작은 단계로 다시 계산한다. 속도나 위치를 벽 바깥으로 덮어쓰지 않는다. 중간·끝 상태의 거리도 검사한다.

최소 메시 거리 0.02mm에 도달하면 `contact_clearance_limit`으로 중단한다. 처음부터 겹친 입력은 `contact_domain_exceeded`로 거부한다. 이런 중단은 전개·회수 완료로 표시하지 않는다.

계산 후에는 별도 OpenCASCADE 검사로 저장된 센서 자세와 와이어를 실제 STEP 솔리드에 겹쳐 본다. 검사한 시각에서 겹침이 없다는 결과와 연속 운동 전체에 대한 증명은 구분한다. CAD 연산 오류는 간섭 없음으로 바꾸지 않는다.

## 범위와 남은 검증

줄이 동체 출구의 모서리나 가이드 곡면을 미끄러질 때는 선분–삼각형 면·모서리의 최소 거리를 사용한다. 평행한 표면에서 접촉 위치가 갑자기 바뀌지 않도록 기존 상자 접촉과 같은 0.16mm 위치 정규화를 적용한다. 힘은 선분 양 끝에 위치 비율로 분배하며 기체에는 같은 위치에서 반력을 준다. 실제 관통 방지 검사는 정규화 전의 전체 메시 거리로 수행한다. 거리 확인만 하는 호출에서는 가장 가까운 점만 읽으며, 힘 계산에 필요한 면 정보와 구분한다.

R3 고익기에서는 윈치 드럼 앞에 별도 줄 안내구를 두고 줄 출입점을 드럼 바깥으로 옮겼다. 이 입력은 `winch.line_attaches_to_drum_center=false`이므로 줄–드럼 충돌도 검사한다. 안내구의 실제 구멍은 오목 메시로 유지한다. 내부 포획 가이드와 동체 출구 끝에서는 한 접촉점이 갑자기 바뀌지 않도록 꼭짓점–면·모서리–모서리의 인접 접촉에 힘을 분배한다. 관통 여부는 전체 원래 메시의 거리로 별도 확인한다.

R3 재계산부터 짧은 접촉 구간의 적분 시각과 중간 시각도 시계열에 남긴다. 일정한 0.01초 출력만으로 놓칠 수 있는 접촉력과 충격량을 보존하기 위한 변경이다. 저장 시각 간격이 균일하지 않으므로 충격량 계산이나 그래프에서는 실제 `time_s`를 사용해야 한다. 최대 접촉력의 수렴과 실물 충격 물성 검증은 여전히 별도 조건이다.

윈치 내부에 감긴 줄의 실제 접촉, 줄 자체의 접촉과 줄–센서 접촉은 포함하지 않는다. 윈치 내부 줄은 기존의 이상적인 출입 경계로 취급하지만, 센서–윈치 충돌은 계산한다. 센서·와이어와 동체·가이드·문·출구 프레임의 관통 수정이 이번 범위다.

줄 분할 수렴, 실제 마찰·탄성·충격 시험 비교, 포획장치와 줄 출입 에너지 수지 검증은 별도다. 수정한 반력 때문에 결과가 이전의 무효 궤적과 달라지는 것은 예상되는 변화다. 포획 성공 여부는 계산 결과 그대로 기록한다.

설치는 프로젝트 가상환경에서 `python -m pip install -e ".[contact]"`로 한다. 이 Windows 환경에서는 PyPI의 PyBullet 3.2.7 소스로 Windows wheel을 빌드해 설치했다.

## 재계산과 독립 검사

프로젝트 폴더에서 아래 명령을 실행한다. 출력 폴더는 기존 결과와 겹치지 않는 새 이름으로 지정한다. 두 시간 간격은 별도 프로세스에서 계산하며, CAD 검사는 여섯 프로세스를 사용한다.

```powershell
.venv/Scripts/python test_models/H1_reference/visualize_run.py --run outputs/h1_contact_new/baseline/mission
```

`verification.json`은 요청 시간 완료, 저장 시각 전체의 CAD 검사 여부, 하중·자세의 시간 간격 차이를 따로 기록한다. 시간 간격 비교가 통과해도 줄 분할 수렴이나 실제 충격 하중 검증을 대신하지 않는다. 중단·취소된 실행은 완료 결과로 불러오지 않는다.

## R3 회수 수정: 둥근 앞코와 정지부

`normal_r3_round_x_sensor_v2`는 센서 앞코를 반경 14mm의 반구로 바꾸고 기존 핀을 45° 돌린 형상이다. 센서 길이 120mm, 몸체 지름 28mm, 가정 질량 40g을 유지하고 CAD 체적 분포로 CG·관성을 다시 계산했다. 센서 CG 좌표가 바뀌어도 외부 견인점 위치·속도는 보존한다.

`normal_r3_round_x_capture_stop_v2`는 이 형상에 원뿔형 정지부를 추가한다. 입구 지름 44mm, 와이어 통과 구멍 지름 16mm, 원뿔 길이 약 22.96mm이며 수납 자세에서 실제 STEP 센서와의 최소 간격은 0.9mm다. 추가 질량 20g은 설계 가정이다. 기체 질량·CG·관성을 갱신하고 모든 기체 기준 형상·견인점·추력점을 같은 새 CG 좌표로 변환했다. 날개·꼬리날개 형상은 같으므로 실제 flow5 7.57의 25m/s 공력표를 재사용하되, 공력 모멘트를 새 CG로 옮겨 계산한다.

정지부 구멍은 오목 메시로 유지한다. 센서·와이어 충돌과 반력 계산에 실제 정지부 형상을 포함하며, 포획 조건 6mm·0.15m/s·8°와 최소 메시 거리 0.02mm는 완화하지 않는다. 포획 후에도 탄성·감쇠 구속으로 움직이며 위치나 속도를 순간적으로 덮어쓰지 않는다.

부품별 감쇠는 다음처럼 지정할 수 있다. `capture_front_stop`의 80·240 N·s/m 비교값은 측정하지 않은 완충부 가정이며, 충격 흡수 장치의 실제 사양이나 검증값이 아니다. 이름이 실제 고정 부품과 다르면 오류로 중단한다. 다른 부품은 기존 전역 접촉 물성을 사용한다.

```yaml
collision:
  feature_engine: numba_bounded
  part_materials:
    capture_front_stop:
      stiffness_N_m: 20000.0
      damping_Ns_m: 240.0
```

`numba_bounded`는 실제 접촉이 가능한 꼭짓점·면·모서리를 모두 남긴다. 거리 하한으로 접촉할 수 없음을 확인한 먼 기하 요소 중, 정규화 전 지수 가중치 합이 1e-24 이하인 항만 제외한다. 지수 절단의 추가 오차 상한은 `N·exp(-700)`이다. `fastmath`나 형상 대체를 쓰지 않는다. 기록된 정지부 접촉 자세와 작은 위치 교란에서 기존 힘·상태 미분과 비교하고, 감쇠를 높였을 때 전체 운동량·각운동량 반작용과 에너지 감소를 검사한다. 이 검사는 메시 수렴이나 실물 충격 검증을 대신하지 않는다.

회수 수정 실행은 `run_capture_stop.py --slow --engine numba_bounded --damping 240 --out <새 출력 폴더>`로 재현한다. 이 명령은 감사된 둥근 센서 결과의 70.811992초 자세에서 시작하는 새 하드웨어 시험이다. 전개부터 전체 임무를 새 형상으로 다시 계산한 결과와 구분한다.

### 곡면 접촉과 와이어 구멍 수정

`--analytic-stop`은 반구형 앞코와 원뿔 정지부의 접촉을 해석식으로 계산한다. 앞쪽 반구가 지지면이 되고 접촉점이 유한 원뿔 내부에 있는 범위에서만 적용하며, 그 밖의 면·모서리·와이어는 기존 전체 메시 계산을 쓴다. CAD 원본 해시를 확인하고 해석식의 곡면 간격을 기존 메시 거리 검사에 추가한다. 접촉력은 원주 256방향에 나눠 적용한다. 기존 메시 접촉력과 완전히 같은 물성 모델이라는 뜻은 아니다.

문 전체 회전 영역과 센서·모든 활성 와이어 구간이 떨어져 있음을 보수적인 이동 거리 상한으로 확인한 경우에만, 적분 간격 상한에서 문 회전 속도를 제외한다. 문과의 거리 검사는 계속 수행한다. 조건이 성립하지 않으면 문 회전까지 포함한 원래 상한을 사용한다.

`normal_r3_round_x_capture_stop_v3`는 와이어 통과 구멍을 22mm로 넓힌 시험 형상이다. 원뿔 길이는 37.714mm이며, 수납 자세의 CAD 간격 0.9mm와 포획 기준을 유지한다. 추가 질량 20g은 여전히 설계 가정이고, 변경된 CAD의 중심과 관성을 다시 반영한다. 구멍 확대만으로 포획·회수 성공을 판정하지 않는다.

### 내부 와이어 공력 수정 시험

기존 계산은 센서의 동체 내부 노출도를 반영했지만, 활성 와이어에는 내부에서도 외부 비행속도의 항력을 적용했다. `run_shielded_capture.py`는 각 와이어 질점에 인접한 두 반구간 중 출구 뒤에 있는 길이 비율을 계산해 공력 노출도를 구한다. 외부에는 지정한 국소 유동 계수를 적용한다. 내부 공기는 기본 시험값으로 기체와 함께 움직인다고 가정하며, 그 공기에 대한 줄의 상대운동으로 항력을 계산한다. 내부 항력의 반력과 모멘트는 기체에도 적용한다.

이 가정은 `flight.cable_bay_shielding: true`, `flight.internal_cable_flow_factor: 0.0`으로 입력 파일에 남는다. 열린 출구의 실제 내부 유동을 해석한 결과는 아니다. 내부 유동 계수는 0–1 범위에서 명시해야 한다. 예전 실행에 쓰인 해석기 사본과 결과는 보존한다.

```powershell
.venv/Scripts/python.exe test_models/H1_reference/run_shielded_capture.py --fast --out test_models/H1_reference/runs/shielded_new --slow --engine numba_bounded --damping 80 --analytic-stop
```

실행 후 `pipeline.json`과 `mission/summary.json`에서 완료·포획·최종 문 각도를 확인하고, 별도 STEP 검사를 수행한다. 부분 궤적에서 포획됐다는 사실만으로 전체 회수 성공이나 시간·줄 분할 수렴을 선언하지 않는다.

`--fast`는 같은 센서 접촉식을 배열로 묶어 계산한다. 반구 전체가 정지부 끝면보다 뒤에 있고 유한 원뿔의 지지 조건이 성립하는 힘 계산에서는 곡면식을 바로 사용한다. 별도의 거리 검사에서는 전체 메시를 계속 조회한다. 기록 자세와 작은 교란 40개에서 기존 상태 미분과의 최대 차이는 7.28e-12, 관통 방지 거리 차이는 0이었다. 이 비교는 두 계산 방식의 일치 검사이며 전체 궤적의 수렴 시험은 아니다.

### 포획 뒤 내부 줄 정리

`run_captured_cleanup.py`는 포획이 확인된 실제 저장 상태에서 시작한다. 이전 회수 명령을 계속하면 내부에 느슨한 줄이 남으므로, 이후 명령만 최대 0.25m/s, 가속·감속 각 0.2초로 바꿔 남은 줄을 감는다. 줄 정리 후 0.2초를 기다린 뒤 문을 0.8초 동안 닫는다. 포획 인터록은 유지하며, 기체·센서·와이어의 위치·속도·자세는 변경하지 않는다. 이 시험 명령은 토크 제한형 모터 제어나 범용 포획 감지 제어기를 구현한 것이 아니다.

앞선 회수 상태는 `accepted_history`의 실제 적분 끝점과 중간점에서 복원한다. 위치를 보간하거나 새로 만들지 않는다. 진단값은 검증된 같은 힘 계산으로 다시 구하고, 전체 메시 거리도 각 저장 시각에서 다시 확인한다. 이후 계산과 연결할 때는 접합 시각의 134개 상태값이 정확히 같은지 확인한다. 포획 순간의 같은 시각·같은 상태에서 힘만 바뀌는 두 행은 보존한다.

연결된 결과를 처음 회수 자세부터 한 번에 다시 적분하려면 다음 명령을 사용한다. 저장된 최종 입력의 윈치 명령을 재사용하므로, 형상이나 포획 조건을 바꾸는 설계 탐색에는 해당 명령 시점도 함께 검토해야 한다.

```powershell
.venv/Scripts/python.exe test_models/H1_reference/rerun_repaired_recovery.py --out test_models/H1_reference/runs/repaired_recovery_rerun
```
