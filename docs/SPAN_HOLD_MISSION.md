# 윙스팬 1.5배 전개 · 60초 유지 · 회수

R3 윙스팬 1.8m를 기준으로 와이어 전개 길이를 2.7m로 설정했다. 완전 전개 후 정확히 60초를 유지하고 회수한다. 이 시간은 센서 고정 해제 시점이 아닌 **2.7m 전개 완료 시점부터** 센다.

| 구간 | 명령 시각 |
|---|---|
| 문 개방 | 0–0.40초 |
| 센서 고정 해제·전개 | 0.60–4.13582초 |
| 2.7m 유지 | 4.13582–64.13582초 |
| 회수 | 64.13582–72.91359초 |
| 포획 후 도어 닫힘 명령 | 73.71359–74.51359초, 포획에 연동 |
| 계산 종료 | 74.91359초 |

길이와 시간을 함께 늘려 기존 전개·회수 속도를 유지했다. 센서가 출구에 접근하는 마지막 0.42m 구간의 속도 이력도 유지한다. 포획되지 않으면 도어 닫힘 명령을 보류한다.

2.7m는 **윈치 가이드에서 센서 견인점까지 풀린 줄의 무변형 길이**다. 동체 내부를 지나는 부분도 포함하며, 센서와 기체 사이의 직선 거리 또는 후방 출구 밖 길이와는 다르다. 줄 분할은 10개에서 18개로 늘려 기존 0.15m 간격을 유지했다. 선밀도 1.5g/m를 적용한 전체 줄 질량은 4.05g이다.

## 입력 파일

- `examples/h1_normal_r3_flow5_span_hold.yaml`: 현재 flow5 임무
- `examples/h1_normal_r3_avl_span_hold.yaml`: 같은 임무의 AVL 입력

기존 연결 시험 입력과 저장 결과는 보존한다. 기체 형상과 공력 조건은 바뀌지 않았으므로 실제 flow5 270조건 공력표를 재사용한다. 줄 길이·줄 질량·작동 시간은 결합 운동 계산에 반영하고, 초기 수납 트림을 다시 계산한다. 자동조종은 추가하지 않는다.

```powershell
# 입력 재생성 (윙스팬은 기존 공력표의 Bref에서 읽음)
.venv/Scripts/python test_models/H1_reference/build_span_hold_case.py --ratio 1.5 --hold 60
# 새 출력 폴더에 실제 전 과정 계산
.venv/Scripts/python -m dbf_stability.cli simulate --case examples/h1_normal_r3_flow5_span_hold.yaml --aero test_models/H1_reference/runs/flow5_connection_01/aerodynamics/aero_database.npz --output outputs/span_hold_new
```

[임무 일정과 계산 결과](../test_models/H1_reference/runs/span_hold_01/report.html)를 확인한다. 일정 그래프는 명령이며, 계산 실패·공력 범위 이탈 등이 발생하면 실제 궤적은 중단 시각까지만 제공한다. 일정이 입력됐다는 사실을 회수·포획 성공으로 해석하지 않는다.

현재 `span_hold_01` 계산은 저장 파일을 읽는 작업과 교체 저장이 겹쳐 Windows 파일 잠금으로 한 차례 중단됐다. 완전히 기록된 임시 체크포인트가 마지막 정상 저장 구간의 상태와 일치하는지 검사하고 1.56009초부터 같은 입력·소스로 재개했다. 읽기 작업은 이후 변경되지 않는 저장 구간 파일만 사용한다. `mission`은 최초 저장 기록, `recovered`는 그 정상 저장 궤적의 복원, `continuation`은 재개 계산이다. 후처리는 실제 계산이 종료된 뒤 실행하며, `combined`에 두 궤적을 상태 변경 없이 연결한다.

일정·도어·길이 경계 관련 검사 10개를 통과했다(`outputs/validation/span_hold_tests.xml`). 전체 임무의 계산 완료 여부는 결과 페이지 상태를 확인해야 한다. `postprocess.json`에 CAD 검사와 재생 생성 진행 상태를 기록한다. 전 과정이 계산됐다는 사실도 포획 성공이나 수치 수렴을 의미하지 않는다.
